# Agent Note: 桌面对话与输入基础能力

Status: proposed

## Problem
编辑与重新生成需要保留可恢复的历史路径；生成中补充要求、长对话压缩和文件输入共享同一条发送生命周期。桌面导航还需要统一项目、编辑器和审阅面板的入口。

## Proposal
- 消息以根 ID 和版本号归组，Conversation 保存备选完整路径及各自摘要边界。分叉事务同时保存旧路径和新版本锚点；版本切换使用同一事务替换当前路径。生成失败或中断时仍保留版本入口。
- 改动压缩边界之前的消息时废弃该摘要，之后的改动保留摘要。摘要从最早未压缩的连续前缀生成，按请求字符预算分批推进边界；原消息保留在 IndexedDB。
- 插话先中止并持久化上一轮，再启动下一轮。发送令牌隔离较晚结束的旧请求，避免清除新请求的互斥状态。
- 文本附件随当前会话保存为发送草稿，异步读取完成后检查会话归属。单文件 16000 字、正文与附件合计 20000 字；超限显示提示。工作区 @ 引用通过现有沙箱读取，支持中文、带空格路径和 README 等文件名。
- 右侧只保留工作区与设置入口，文件统一进入主编辑器。检查点恢复清空编辑缓冲并使旧异步读取失效，避免恢复后误写过期内容。右侧面板独立拖动调整宽度。
- 执行模式为只读、需确认、全自动，默认需确认；旧自动开关不迁移为全自动。上下文用量是基于应用 24000 字请求预算的估计值，超过一半才显示。

## Alternatives considered
- 直接覆盖历史会使编辑失败无法恢复。每个版本保存完整路径占用更多空间，但不需要改现有消息主键或新增树遍历协议。
- 只按消息数压缩不能覆盖少量大消息；只取最近消息做摘要会跳过更早事实。
- 在右侧重复提供编辑器会造成两份缓冲和工作区状态。

## Acceptance criteria
- 编辑、重新生成失败、重载和双向版本切换均可保留历史。
- 插话不会混入旧流，压缩边界不越过未纳入摘要的消息。
- 键盘命令面板、文件输入、窄窗口弹层和审阅面板调整可通过实际浏览器验证。
- 类型、静态检查、单元、桌面端、浏览器与性能门禁通过。

## Risks
完整路径随版本数量增长。摘要和上下文用量均依赖模型输出与字符估算；文件引用仍受读取上限约束。检查点只覆盖工作区文件，授权与回滚的完整契约单独记录。
