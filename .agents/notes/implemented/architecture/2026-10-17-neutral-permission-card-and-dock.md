# Agent Note: 权限审查卡片中性化契约、三态操作与等宽折叠布局

Status: implemented

## Problem

原桌面端写类工具授权卡片（`PermissionCard`）存在以下几处视觉与交互体验问题：
1. **文案拟人化与主观倾向**：标题文案采用“八千代请求执行终端命令”、“八千代请求修改工作区文件”等第一人称表述，与现代化桌面 AI 工具（Codex、Antigravity、Claude 桌面版）中立、严谨的安全审查语言风格不符；
2. **操作层级与快捷键失衡**：原卡片操作分为“拒绝”、“本次允许”与“总是允许此类命令”，默认快捷键为 `Ctrl+Enter`，增加了快捷键记忆负担且与日常习惯不一致；
3. **参数过度展开占用视线**：文件写入操作（如 `write_file`）在卡片中直接平铺展开大段格式化 JSON 参数，造成信息噪声并严重挤占输入区垂直空间；
4. **色彩与质感不符合极简规范**：使用了刺眼的琥珀黄高光边框、红色拒绝背景以及彩色代码高亮，且缺少 `prefers-reduced-motion` 减弱动效适配。

## Decision

- **中性文案契约**：
  - 终端命令执行统一为：“允许运行此命令？”（日文：“このコマンドの実行を許可しますか？”）；
  - 文件修改/写入统一为：“允许修改此文件？”（日文：“このファイルの変更を許可しますか？”）；
  - 外部服务或 MCP 工具统一为：“允许调用 <服务> 工具？”（如 `允许调用 github 工具？`）；
  - 纯函数 `parsePermissionArguments` 支持可选 `locale` 参数，确保中日双语平滑降级。
- **三态操作按钮与直觉快捷键**：
  - **允许一次**：主操作按钮，高对比度中性灰阶呈现，绑定 `Enter` 快捷键，触发 `onApprove(false)`；
  - **本会话允许**：次要线框按钮，触发 `onApprove(true)`；
  - **拒绝**：次要线框按钮，绑定 `Esc` 快捷键，触发 `onDeny()`；
  - 针对键盘事件进行焦点防穿透处理：当卡片内具体按钮或输入控件处于聚焦状态时，按回车尊重原生按钮触发，避免误拦截。
  - 在 `DesktopChatArea` 层面进行联动：当存在待决权限卡片（`pendingPermission`）时，输入框内按 `Enter` 触发单次批准而非发送草稿，按 `Esc` 触发拒绝。
- **信息紧凑化与等宽详情折叠**：
  - 命令展示采用平铺等宽块（`var(--ds-font-family-code)`），内嵌复制按钮；
  - 文件修改工具仅展示单行目标路径与一行说明（来源自 `Description` 或 `Instruction`），完整 JSON 参数收纳于 `<details>`（详情 / 詳細）折叠容器内；
- **全量中性设计令牌与无障碍适配**：
  - 移除硬编码颜色与彩色光晕，全量映射至 `tokens.css` 语义令牌（`--dsw-alias-bg-layer-*`、`--dsw-alias-border-l*`、`--dsw-alias-label-*`）；
  - 快捷键键帽采用中性微型 `<kbd>` 标注；
  - 新增 `@media (prefers-reduced-motion: reduce)` 适配规则，系统开启减弱动效时直接关闭入场动画与过渡效果。

## Alternatives considered

- 保留“总是允许此类命令”文案：语义容易产生长期全局持久化的歧义，实际上受限于当前会话生命周期，改为“本会话允许”更加精准诚实。
- 快捷键仅保留在鼠标悬浮的 title 中：降低了键盘直觉盲操效率；增加微型 `<kbd>` 标注可显著降低认知负荷。

## Consequences

- 桌面输入区上方安全审查卡片视觉更加严谨专业、克制平铺；
- 开发者可以通过回车与 Esc 极速决策授权，同时保留本会话持续允许通道；
- 既有 `onApprove` 与 `onDeny` 接口协议保持 100% 兼容。
