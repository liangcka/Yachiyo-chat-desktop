# Agent Note: 消息事件顺序与桌面对话布局

Status: implemented

## Problem

消息分别聚合正文、思考与工具步骤时，展示层无法区分工具执行前后的正文。固定将工具置顶会让授权说明出现在执行结果之后。桌面对话同时存在外层卡片、顶栏控制和输入区控制，挤占正文空间。

## Decision

- `ChatMessage.contentSegments` 保存正文、思考和工具调用的到达顺序。正文与思考使用现有字符串的 UTF-16 起止偏移，工具使用调用 ID，不重复保存全文或工具输出。
- 流式缓冲仅合并相邻同类增量，在工具调用前提交待处理增量。界面投影、定时持久化，以及完成、停止、失败三个终态都携带顺序快照。
- 思考片段的耗时从首个思考增量到下一类内容事件或终态计算。连续思考增量合并为同一片段；后续工具与正文耗时不计入该片段。
- 流式阶段按片段顺序实时渲染，只有相邻工具调用合并为一组。完成后，有工具步骤且存在最终正文的多片段回复，将最后一段正文之前的过程收为一行摘要；展开后恢复原顺序。普通回复、停止与失败记录保留逐段展示。
- 过程与最终正文由纯函数拆分。摘要显示工具步数和失败步数；仅在首片段的开始时间、最后一个思考或工具片段的结束时间均可取得时显示总耗时。工具片段未记录时间戳时省略耗时，不累加工具执行时长，也不使用整条消息延迟代替。
- 流式思考默认收起全文，仅展示最新一行并截断超长内容；手动展开期间继续实时更新，正文开始后收起。已计时且不足一秒的片段显示“思考了不到 1 秒”。
- 待批工具名只传给当前助手回复，并匹配同名工具中最后一个未完成步骤；待批时显示“等待批准”，批准后恢复执行指示。失败步骤展开后优先显示错误输出，参数保留在详情内。
- 成功结果不展示完成徽标，失败在过程摘要、工具组与明细中提示。过程控件使用中性色和主题变量，失败计数使用错误色，键盘焦点环使用焦点变量。
- 缺少顺序字段的旧记录按思考、工具、正文展示；缺少计时数据时使用“查看思考”。存储索引和数据库版本保持现有契约。
- 桌面侧栏、对话区和成果区采用分割线布局。项目、模式、联网、技能、模型与成果入口集中到输入区；消息操作在末尾悬停或键盘聚焦时显示。欢迎页使用本地用户名与时间问候，建议入口采用输入框下方的小标签。

## Alternatives considered

- 只调整工具、思考、正文三个固定区块的顺序：无法表达多轮工具调用之间的正文。
- 为每个事件重复保存完整正文或思考：增加流式快照和本地存储开销。
- 替换原有 `text`、`thought`、`toolSteps`：扩大请求历史、复制功能与已有存储的迁移范围。
- 根据旧正文内容推测工具位置和思考耗时：缺少可靠数据，无法保证还原结果。

## Consequences

新回复在流式阶段和重新打开会话后保持相同的内容顺序；完成记录默认将最终答案前的过程折叠，重新加载后仍默认收起。复制正文及生成请求历史仍读取原有聚合字段。旧消息的真实交错顺序无法恢复，思考耗时也不包含首个思考增量到达前的服务端等待时间；缺少过程边界时间戳的记录只展示步数。

## Verification

- `npm run test:unit`：58 个测试文件、474 项测试通过，包含过程拆分与边界计时、终态折叠、流式思考预览、同名工具待批匹配、中日文文案和失败输出回归测试。
- `npm run typecheck`：三份 TypeScript 配置通过；`npm run dev:mock` 前置生产构建通过。
- `npm run lint`：无错误；`ConversationView` 存在既有的 React Compiler 与虚拟列表兼容性警告。
- `npm run test:perf`：120 条消息的窗口化、虚拟化与交互长任务检查通过。
- 本地 Pages Functions Mock 浏览器检查：使用确定性 SSE 事件验证摘要、原序展开、失败输出、重载折叠、思考最新行省略、待批无转圈以及 Enter 批准后恢复执行指示；浅色与深色截图正常，无控制台错误或横向溢出。
