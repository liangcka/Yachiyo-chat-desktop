# Agent Note: 回复过程摘要与无项目文件工具契约

Status: implemented

## Problem

多轮工具调用中的思考、过渡文字和工具组占据大量纵向空间。工具执行耗时不包含批准等待，不能直接用来表示整轮处理时间。未选择项目时拒绝所有文件读取，会诱导模型转用命令行；命令行写入也无法提供文件工具的检查点和代码审阅语义。

## Decision

流式回复保留内容片段的原始顺序。完成且含有工具过程的回复，将最后一个正文片段之前的内容收在一行摘要内；纯函数负责拆分，不改动持久化正文或请求历史。没有工具、没有最终正文或只有一个片段时保留原展示。

消息记录首片段开始时间，工具步骤记录开始与结果到达时间，均使用相对本轮请求开始的毫秒数。摘要从首片段开始计时，截止最后一个思考或工具片段结束，包含批准等待，不包含最终正文。缺少完整时间戳的历史记录仅展示步数。

无项目的 read_file 和 list_directory 接受用户提供的绝对路径；确认和只读模式通过现有权限卡批准，完全访问模式直接执行。无效路径在审批前返回错误，避免等待无法执行的批准。执行边界独立检查授权、绝对路径及检查点私有存储限制；已有项目的文件边界保持工作区范围。write_file 始终要求项目，失败结果固定为“当前任务未绑定项目，无法写入。请让用户在输入框上方为本任务绑定项目。”，工具卡提供为当前任务绑定项目的入口。

中日系统提示词与工具描述均要求文件读写使用 read_file / write_file，run_command 仅用于构建、测试、git 和查询系统信息。Windows 命令进程在执行前将 Console 输入、输出及 PowerShell 管道编码设为无 BOM 的 UTF-8。

## Alternatives considered

- 用整条回复延迟或工具 durationMs 累加：前者包含最终回答，后者遗漏批准等待及过渡片段，均不符合耗时边界。
- 把无项目读取归为写类工具：会令只读模式无法批准读取，也会错误触发写入检查点。
- 让模型用 PowerShell 读写文件：绕过文件观察和审阅契约，且增加编码差异。
- 用命令字符串匹配强制禁止所有文件操作：别名、嵌套 shell 和构建工具副作用无法可靠分类；本阶段通过明确提示词约束模型选用工具，保留既有命令执行授权边界。

## Consequences

可选时间字段兼容现有 IndexedDB 记录，无需数据库迁移。无项目读取的授权按工具参数复用现有权限范围，不授予默认用户目录的隐式读取权限。提示词约束不等价于命令沙箱；命令执行仍受现有执行模式、审批和危险命令检查控制。
