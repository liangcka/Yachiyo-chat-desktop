# Agent Note: 工作台端到端测试入口与布局契约

Status: implemented

## Problem

应用直接进入工作台并在后台建立会话。端到端测试仍依赖访问码页、旧手机版菜单与扬声器控件，无法验证当前界面，也使 CI 长时间等待不存在的元素。

## Decision

- 共用进入函数等待输入框可用，并在浏览器内查询真实 Mock 后端的会话状态。浏览器与请求客户端对本地 HTTP 地址的 Secure Cookie 处理存在差异，因此会话检查使用与应用一致的浏览器上下文。
- 聊天、搜索和动效用例使用现有工作台、账户菜单及设置中心入口，同时覆盖完整侧栏和紧凑侧栏。
- 消息步骤顺序在展开执行过程后验证；重载后验证过程和工具组默认折叠。版本切换先悬停消息，遵守操作栏的显示条件。
- 布局断言验证回复、输入区与提示之间没有遮挡，并检查窗口横向溢出。保留 390px 与 1440px 两组项目以及原有桌面专用用例的跳过条件。
- 减少动态效果时验证取消位移和输入卡过渡，允许界面保留淡入反馈。

## Alternatives considered

- 恢复旧访问码页和手机版控件：与当前工作台的产品入口不符。
- 删除失败用例、增加重试或放宽超时：无法提供当前交互行为的回归证据。
- 伪造会话成功响应：会掩盖真实后台鉴权与首次发送的竞争问题。

## Consequences

端到端测试跟随当前可见入口，继续覆盖发送、流式回复、离线恢复、PWA 提示、中日语言、附件、搜索来源、消息版本和动效。测试不修改生产鉴权逻辑或 CI 门禁。
