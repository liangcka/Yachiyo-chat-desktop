# Agent Note: 桌面对话与工作区的界面层级

Status: implemented

## Problem

桌面界面的渐变、阴影和胶囊控件分散了对话内容的注意力。三栏同时展开时，中栏的有效宽度与窗口宽度不同，欢迎页和成果标签需要按可用空间调整。

## Decision

- 顶栏、侧栏、对话区、成果面板与设置页复用现有主题语义变量，以间距、轻边框和明确的操作层级组织内容。
- `DesktopWelcome` 负责欢迎页呈现与中日双语引导，输入区始终挂载于 `DesktopChatArea`，首次发送通过位置过渡落到底部。
- 侧栏底部提供独立设置入口，应用顶栏统一承载侧栏折叠操作。
- 欢迎页通过中栏容器宽度切换话题排列；窄桌面窗口中的成果面板覆盖中栏，标签横向滚动，关闭操作保持可见。
- 应用统一使用已有的桌面入口，删除闲置的 `MobileLayout` 和设备模式 Hook；Android / Capacitor 原生工程、平台适配与共享组件继续保留。
- 保留既有文档文件和历史记录，README、架构指南与贡献指南同步当前桌面入口。此次变更仅作用于 `Yachiyo-chat-desktop` 仓库。

## Alternatives considered

- 仅在样式文件末尾覆盖全部旧规则会保留相互竞争的主题声明，因此直接调整相关组件规则并删除重复声明。
- 以整个窗口宽度控制欢迎页，无法覆盖左右面板展开后中栏变窄的情况，因此采用容器查询。
- 删除 Android / Capacitor 工程会超出仅移除移动版界面的范围，因此保留原生工程及其依赖。

## Consequences

对话和输入操作获得更清晰的视觉层级。欢迎文案集中管理，现有聊天、编辑器和成果面板继续复用同一套业务状态。窗口较窄时需要滚动查看部分内容，成果面板可以通过原有按钮与快捷键关闭。

## Verification

- `npm run build`，包含三份 TypeScript 配置的类型检查。
- `npm run lint`：零错误，现有虚拟列表组件保留一条 React Compiler 兼容性警告。
- `npm run test:unit`：43 个测试文件、384 项测试通过。
- `DesktopLayout.test.tsx` 专项验证：20 项测试通过，覆盖独立设置入口和现有桌面交互。
- 带 Pages Functions 的本地 Mock 浏览器联调：深浅主题、中日文欢迎页、消息发送与回复、侧栏折叠及不同桌面窗口宽度。
- 既有文档文件继续保留，主题颜色、Android 工程和 Capacitor 配置没有变更。动态效果与挂件移除的验证见同目录 `2026-10-17-desktop-composer-motion.md`。
