# Agent Note: 未绑定项目的 Agent 使用临时项目并可读写项目外文件

Status: implemented

## Problem

未绑定项目的任务只能读取用户给出的绝对路径，`write_file` / `edit_file` 一律返回“未绑定项目，无法写入”，`glob` / `grep` 也不可用。用户只是想让 Agent 写一个自我介绍 HTML 放到桌面，也必须先找一个文件夹绑定为项目，与“项目”的本意不符。

## Decision

- **临时项目**：`tools::scratch_root()` 给出所有未绑定任务共用的临时项目目录 `~/.yachiyo/scratch`（按需创建）。无项目时相对路径的文件工具、`glob` / `grep` 与 `run_command` 的工作目录都以它为根（`tools::working_root`），越界、`..` 与检查点私有路径沿用工作区边界拒绝。
- **项目外文件用绝对路径**：`tools::file_write_root(path, None)` 对临时项目外的绝对路径返回最近的已存在上级目录作为写入边界（`fs::unbound_write_root`），因此可以在桌面等位置新建目录与文件；应用自身数据目录（密钥、审批范围、检查点）不开放写入，含 `..` 的路径直接拒绝。
- **授权与项目内一致**：写入（无论临时项目内外）在确认模式下逐次走权限卡，只读模式拒绝，完全访问直接放行；临时项目内的读取、列目录与检索如同项目内直接执行；临时项目外的读取仍需路径级授权（`is_unbound_file_read` 按路径判定）。`approval_key` 按执行时同样的规则解析写入目标，批准范围与实际写入一致。无效路径在 Agent 循环中直接返回错误，不进入批准等待。
- **不做项目级追踪**：未绑定任务的 `workspace_root` 仍为 `None`，不建检查点、不进改动账本与任务审阅，也不加入项目列表与运行归属。
- **提示词**：无项目时系统提示词给出临时项目与桌面的真实路径（桌面经 `dirs::desktop_dir()` 识别 OneDrive 等重定向），并要求用户指定了存放位置的成品直接写到该位置。未绑定任务的项目条说明任务在临时项目中工作、可在确认后读写桌面等位置的文件。

## Alternatives considered

- **只放开桌面**：能覆盖“放到桌面”的场景，但文档、下载等其他位置仍要先绑定项目；改为任意绝对路径加逐次确认。
- **把临时项目作为运行的 `workspace_root`**：可以复用检查点与任务审阅，但运行归属、项目列表与界面绑定都会把临时目录当成真实项目，且工作区边界会挡住项目外的绝对路径。
- **每个对话一个临时目录**：隔离更好，但需要把对话编号贯穿所有工具调用；共享目录与同类产品的 scratch 目录一致，足以承载草稿与中间产物。

## Consequences

- 无项目任务可以直接产出文件到桌面等任意位置，确认模式下每次写入都有权限卡把关；这些写入无法从任务审阅中撤销。
- 所有未绑定任务共享同一个临时项目，文件不会自动清理，彼此可见。
- 无项目时 `run_command` 的默认工作目录从用户主目录改为临时项目。

## Verification

- `cargo test --manifest-path src-tauri/Cargo.toml`：`unbound_file_tools_tests` 覆盖临时项目内相对路径的写读列检索（仅写入需确认）、项目外绝对路径写入在各执行模式下的授权、`..` 越界路径直接报错且不等待批准、先读后写的覆盖、写入批准键按解析后的目标计算。
- `npm run typecheck`、`npm run lint`、`npm run test:unit`。
