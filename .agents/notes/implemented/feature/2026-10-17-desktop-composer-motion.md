# Agent Note: 桌面输入区位置过渡与挂件移除

Status: implemented

## Problem

首次发送消息会把输入区从欢迎页卸载，再挂载到底部，造成位置跳变和焦点丢失。右下角挂件遮挡输入与话题入口，部分使用文档仍将手机界面描述为当前产品。

## Decision

- 输入区始终挂载于 `DesktopChatArea` 的同一层级。欢迎内容与消息区域切换，CSS 调整输入区在布局中的位置。
- 发送入口共用 `prepareTransition`，在提交前读取输入区位置；消息进入视图后，仅对输入区的 `transform` 播放 250ms 的 Web Animations API 过渡。时长与缓动读取现有主题动效变量，不延迟发送请求。
- 只连接当前空白会话的首次发送，不在加载历史、后续发送或流式更新时重复播放。切换会话、窗口尺寸变化、系统动态效果偏好变化和组件卸载时取消动画并清理订阅。
- 欢迎内容轻量淡入，话题箭头仅在支持精细悬停的设备上移动。系统要求减少动态效果时，输入区直接就位，欢迎内容仅保留短暂淡入。
- 移除 Live2D 组件、对应测试、加载入口、样式覆盖、设置开关及本地设置字段。旧存储中的未知字段会在读取时被忽略；保留用户的名称、头像和称号。历史素材继续保留，应用不请求其资源。
- 更新 README、架构指南、贡献指南与交接说明，新增桌面使用指南和当前桌面截图；历史设计记录明确其时效。PWA 不再限制竖屏，性能验证使用桌面视口。
- 改动限定于 `Yachiyo-chat-desktop`；Android / Capacitor 原生工程继续保留。

## Alternatives considered

- 在新挂载的输入区上播放固定距离动画，无法保证不同窗口、多行输入和侧栏宽度下的位置连续，也不能保留原输入节点。
- 引入动画库会增加仅一次位置过渡的依赖成本；Web Animations API 已支持所需的位移、取消与完成回调。
- 仅关闭看板娘默认开关会保留脚本加载和重新启用的入口，因此移除应用接入层。

## Consequences

首次发送保留焦点与现有输入节点。位移动画使用实际几何差值，窗口变化时直接回归最终布局。旧浏览器不支持 Web Animations API 时直接就位。历史移动端和挂件素材仍在仓库中，但不属于当前界面功能。

## Verification

- `npm run test:unit`：43 个测试文件、384 项测试通过，覆盖位置过渡、减少动态效果、会话切换、尺寸变化清理及真实桌面输入节点与焦点的保留。
- `npm run lint`：零错误；保留虚拟列表组件已有的 React Compiler 兼容性警告。
- `npm run build`：提示词同步、三份 TypeScript 配置检查和 Vite / PWA 构建通过。
- `npx playwright test --config playwright.perf.config.ts`：桌面视口通过 120 条消息的虚拟化、历史窗口和发送阶段长任务检查；进入流程与当前直接显示桌面的行为一致。
- 浏览器检查：首次回车发送后输入区从欢迎页移至底部，保持焦点；`Shift+Enter` 保留两行草稿而不发送。页面与外观设置均无看板娘，欢迎页无横向溢出，当前桌面截图已同步至 README。
